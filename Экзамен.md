-Конструктор базового класса всегда вызывается первым - это гарантия языка
-Деструктор базового класса всегда вызывается последним
-Это обеспечивает безопасную и предсказуемую инициализацию/очистку
-Можно контролировать, какой конструктор базового класса вызывать
Нельзя не вызывать конструктор базового класса (кроме тривиальных случаев)

# Virtual - наследование


## **Ключевые отличия: Обычное vs Виртуальное наследование**
| Аспект | Обычное наследование | Виртуальное наследование |
|--------|----------------------|---------------------------|
| **Количество экземпляров базового класса** | Каждый производный класс содержит свою собственную копию базового класса | Все классы, наследующие виртуально, разделяют ОДИН общий экземпляр базового класса |
| **Размер объекта в памяти** | Больше (из-за дублирования данных базовых классов) | Меньше (нет дублирования), но добавляются указатели для доступа к общему базовому классу |
| **Доступ к членам базового класса** | Может требовать явного указания пути доступа при неоднозначности (например, `d.B::value`) | Прямой доступ без неоднозначности, так как член существует только в одном экземпляре |
| **Инициализация базового класса** | Каждый конструктор производного класса инициализирует свою собственную копию базового класса | Самый производный класс в иерархии отвечает за инициализацию общего базового класса |
| **Производительность доступа к данным** | Быстрее (прямой доступ к данным, расположенным внутри объекта) | Медленнее (косвенный доступ через указатель или смещение) |
| **Использование при множественном наследовании** | Приводит к дублированию базового класса ("алмазная проблема") | Решает проблему дублирования при ромбовидной иерархии |
| **Синтаксис объявления** | `class B : public A { ... }` | `class B : public virtual A { ... }` |
| **Влияние на иерархию классов** | Простое, предсказуемое поведение | Более сложная семантика, требующая понимания порядка инициализации |
| **Типичное использование** | Большинство случаев наследования, где не ожидается множественное наследование от одного базового класса | Интерфейсы, абстрактные классы, решение "алмазной проблемы" при множественном наследовании |
| **Неоднозначность при приведении типов** | При приведении через разные пути могут получаться разные адреса одного базового класса | Все пути приведения ведут к одному и тому же экземпляру базового класса |

## **Рекомендация:**
Используйте **виртуальное наследование** только при необходимости решения проблемы дублирования базового класса в ромбовидных иерархиях. В большинстве случаев **обычного наследования** достаточно и оно обеспечивает лучшую производительность.


# Public, private, protected наследование
## **Public**
Семантика:
- "Является" (is-a) отношение
- Derived - это специализированный Base
- Наследует интерфейс и реализацию

| Модификатор в Base | Доступ в Derived |
|--------------------|------------------|
|public	             |   public         |
|protected	         |   protected      |
|private	         |   нет доступа    |

Когда использовать:

- Классическое ООП-наследование
- Полиморфизм (с виртуальными функциями)
- Расширение функциональности базового класса

## **Private**
Семантика:
- "Реализован посредством" (implemented-in-terms-of)
- Derived использует реализацию Base, но не является Base
- Все члены Base становятся private в Derived

| Модификатор в Base | Доступ в Derived |
|--------------------|------------------|
|public	             |   private        |
|protected	         |   private        |
|private	         |   нет доступа    |


Когда использовать:
- Композиция не подходит, нужен доступ к protected членам
- Нужно переопределить виртуальные функции Base
- EBO (Empty Base Optimization) - оптимизация размера

## **Protected**
Семантика:
- Промежуточный вариант между public и private
- Предназначен для дальнейшего наследования
- Все public члены Base становятся protected в Derived

| Модификатор в Base | Доступ в Derived |
|--------------------|------------------|
|public	             |   protected      |
|protected	         |   protected      |
|private	         |   нет доступа    |

Когда использовать:
- Создание промежуточных базовых классов в сложных иерархиях
- Когда нужно ограничить интерфейс для внешнего кода, но сохранить для дальнейшего наследования
- Практически никогда - обычно есть лучшие решения


# указатель на функцию
- это переменная, которая хранит адрес исполняемого кода функции, позволяя вызывать её динамически, передавать как аргумент и использовать для реализации колбэков или массивов функций.

```cpp
int (*pAdd)(int, int); // Объявление указателя на функцию
pAdd = &add;           // Присвоение адреса функции 'add'
// Или просто: pAdd = add;
std::cout << "Через указатель: " << (*pAdd)(5, 3) << std::endl; // Вызов через указатель
std::cout << "Напрямую: " << add(5, 3) << std::endl; // Прямой вызов
```
